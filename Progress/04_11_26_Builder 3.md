## 2. Instructions for Other Team Members: Requirements & Setup

To ensure all team members can set up the environment and run the tests without encountering Python dependency or environment issues, follow these instructions:

### 2.1. 1-Click Automated Setup (Windows — Recommended)
1. Open folder `group03-smartschedule-baseline/`.
2. Double-click **`setup_env.bat`**.
3. The script will:
   - Check for Python 3.12+ in your system `PATH`.
   - Create an isolated virtual environment (`.venv`).
   - Activate `.venv`, upgrade `pip`, and install all packages from `requirements.txt`.

Open your terminal in `group03-smartschedule-baseline/` and run:
```bash

.venv\Scripts\activate.bat
# macOS / Linux:
source .venv/bin/activate

# 3. Upgrade pip and install dependencies
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## 5. Directory Breakdown & Test Case Inventory

### 5.1. UI Tests (`verification_tests/ui_tests/` — 6 tests)
- **`test_ui_endpoints.py`:** Workbench HTML/JS delivery, preset retrieval, scenario loading, manual drag-and-drop validation (`/api/validate-move`), and calendar export compliance.
- **`test_ui_contract_improve_plan.py`:** Verifies the full ISO-8601 JSON Data Contract specified in [improve_plan.md §7.3](file:///d:/Projects/Computational-Thinking---Group-Project/Improve_Plan/improve_plan.md#L596-L644) (`now`, `week_start`, `reasons[]`, `allowed_starts`, and `metrics`).

### 5.2. Architecture Tests (`verification_tests/architecture_tests/` — 9 tests)
- **`test_system_architecture.py`:**
  - *AST Boundary Audit:* Statically inspects AST of domain solvers to guarantee zero imports of `web` or `fastapi`.
  - *Data Layer Purity:* Asserts `src/models.py` never imports `controller` or `solvers`.
  - *Solver Statelessness:* Verifies solver instances retain no cached state across sequential runs.
  - *Mask Tamper-Resistance:* Proves `remove_block()` cannot clear locked `SLEEP` or `OCCUPIED` masks.
- **`test_memory_leaks.py`:**
  - *Heap Stability:* `tracemalloc` tracks net memory over 50 consecutive full solves ($< 350\text{ KB}$ growth).
  - *Peak Memory Bounds:* Asserts single-solve peak memory is bounded $< 10\text{ MB}$.
- **`test_production_failures.py` [Edge Cases]:**
  - *Concurrent Thread Safety:* Simulates simultaneous requests from Student A and Student B; proves zero block leakage between threads.
  - *Scale Latency SLA:* Stresses solver with 50 tasks; asserts solving latency is strictly $< 2000\text{ ms}$.
  - *Timezone Offset Handling:* Tests foreign timezone offsets (`-05:00` New York); verifies graceful handling without internal 500 errors.

### 5.3. Logical Tests (`verification_tests/logical_tests/` — 16 tests)
- **`test_circular_dependencies.py`:** Traps mutual cycles ($A \leftrightarrow B$), self-loops ($A \to A$), and transitive 3-node cycles ($A \to B \to C \to A$) without infinite recursion.
- **`test_undefined_behaviors.py`:** Guards against illegal hours (`"25:00"`), slot out-of-bounds queries, empty inputs, negative durations, and priority clamping ($1 \le p \le 5$).
- **`test_generation.py`:** Parameterized test generator evaluating random tasks across `EDF`, `LST`, and `WSPT` while verifying $C_{\text{hard}} = 0$ continuously.
- **`test_scheduling_edge_cases.py` [Edge Cases]:**
  - *Simultaneous Deadline Priority Inversion:* 3 tasks due at identical deadlines with tight capacity; proves that high-priority tasks (P5) are preserved while low-priority tasks (P1) are dropped.
  - *Sunday Boundary Overflow:* Tests task ending past Sunday midnight; proves slot indexing does not wrap around to Monday slot 0.
  - *Extreme 15-Minute Slot Fragmentation:* Partitions 4 hours of free time into sixteen 15-minute non-contiguous slots; proves an atomic 60m task is correctly flagged as unplaced without violating classes.
  - *Sprint Mode Compression Recovery [Target Failure]:* Tests whether a task missing a deadline by 15m can trigger Sprint Mode compression rather than being dropped.

### 5.4. Benchmark Tests (`verification_tests/benchmark_tests/` — 20 tests)
- **`test_time_grid.py`:** Discrete grid mathematics and 672-slot breakdown verification.
- **`test_constraints.py`:** Hard constraints H1–H5 zero violations on Minh and Lan presets.
- **`test_edf_solver.py`:** 3x SHA-256 hash equality (determinism) and local repair stability ($S_{\text{stability}} \ge 90\%$).
- **`test_scenarios_t01_t10.py`:** End-to-end integration across all 10 standard course scenarios (T01–T10).
- **`test_feasibility_benchmarks.py` [Solvability Proofs via Response Retrieval]:**
  - *Tight Feasible Single Gap (Possible):* Evaluates exact 120m placement into a 120m gap with 0 slack.
  - *Capacity Shortage (Impossible):* Mathematically proves a 60m shortage; asserts that response retrieves `CAPACITY_SHORTAGE` with `shortage_minutes == 60`.
  - *Fragmentation Barrier (Impossible):* Evaluates 150m atomic task against two 90m gaps; asserts retrieval in `unplaced_tasks` without class overlap.
  - *Prerequisite Dependency Chain (Possible):* Verifies sequential execution ($\text{Arch} \to \text{Impl} \to \text{Test}$).
  - *Deadlocked Zero Free Window (Impossible):* Verifies midnight tasks before 06:00 are unplaced without violating protected sleep ($H_2$).
